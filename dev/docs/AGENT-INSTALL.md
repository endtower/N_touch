# 给安装这台程序的 AI 助手

> **这份文件写给 AI，不是写给普通用户。**
> 用户通常不会自己看完安装步骤，而是把 `AbyssLauncher.exe` 交给你，说"帮我装好"。
> 按下面的顺序做，每一步都有**判断标准**。做完一步再做下一步，不要跳。

程序名叫「弱链接 / WeakLink」。它是一个本机 AI 助手（Core）+ 一个桌面启动器。
---

## 0. 先明确三件事

| 事实 | 说明 |
|---|---|
| **只有一个 EXE** | 用户给你的就是 `AbyssLauncher.exe`，没有任何安装包、没有 Python、不需要管理员权限 |
| **EXE 不会自动装 Core** | 第一次打开时 Core 显示"未安装"是**正常的**。必须手动选版本下载，这是最容易漏的一步 |
| **数据在单独目录** | 程序和数据分开；更新程序不覆盖用户数据，删程序也不会删记忆 |

程序会装到：

```
%LOCALAPPDATA%\Abyss\app     ← 程序
%LOCALAPPDATA%\Abyss\data    ← 数据（记忆、配置、日志）；绝对不要删
```

---

## 1. 让用户双击 EXE

**你来做**：请用户双击 `AbyssLauncher.exe`。

**判断标准**：出现标题为「弱链接」的窗口，左栏能看到「总览与控制」。
如果 Windows 弹「已保护你的电脑」→ 让用户点「更多信息」→「仍要运行」。这是未签名程序的正常提示，不是中毒。

> 如果用户把 EXE 放在别处（比如桌面），首次运行会把它自己复制到 `%LOCALAPPDATA%\Abyss\app`。
> 之后**始终从那个位置启动**，不要同时开两份，会抢端口。

---

## 2. 装 Core（关键一步，别漏）

**你来做**：在窗口中找到 `弱链接 Core` 这一行。

1. 点这一行展开；
2. 在版本下拉里选**最新的正式版**；
3. 点行尾的**下载图标**（向下的箭头）；
4. 下载完成后，**同一个图标会变成"安装"**，再点一次，弹出确认窗口后确认。

**判断标准**：Core 那一行状态变成「已安装 / 未启动」，版本号显示出来。

> ⚠️ **这一步必须联网**（访问 GitHub 和模型 API 域名）。
> ⚠️ 如果用户网络访问慢或失败，不要教他去解压 zip；让他在展开区用「导入本地包」，选 `packages\` 里的 `core-<版本>.zip`（zip 和同名 `.json` 必须在一起）。
> ⚠️ 不要用管理员权限运行。

---

## 3. 第一次启动 Core：填身份和模型

**你来做**：点 Core 行的**启动**按钮。

会弹出「首次启动 Core」窗口，填这些：

| 字段 | 填什么 |
|---|---|
| 你的 QQ 号 | **用户本人的 QQ**（主人）。私聊白名单和审批都认它 |
| 你的称呼 | 机器人怎么称呼用户，默认「主人」 |
| 助手登录的 QQ 号 | **机器人自己的 QQ**，必须和后面 SnowLuma 登录的号一致 |
| 助手名称 | 机器人自称，默认「助手」 |
| 模型 API 地址 | OpenAI 兼容地址，默认火山方舟 `https://ark.cn-beijing.volces.com/api/plan/v3` |
| 模型名称 | 默认 `DeepSeek-V4.1-Flash`，必须和供应商给的模型 ID **完全一致** |
| API Key | 用户的密钥。让**用户自己粘贴**，你不要让他把 Key 发到聊天里 |

两个 QQ 号必须是纯数字，否则保存会报错。

**判断标准**：保存后 Core 启动，左栏状态显示「运行中」，版本号正确。

> 这里填的东西会写进 `%LOCALAPPDATA%\Abyss\data\.env.dev`，更新 Core 不会丢。
> **绝不要把 `.env.dev`、令牌、API Key 的内容贴进聊天或截图。**

---

## 4. 验证模型能用（可选但强烈建议）

**你来做**：左栏点「管理页面」打开管理控制台 → 顶部「系统」→ 左侧「模型接入」→ 在 common 卡片点「**测试连接**」。

**判断标准**：

- 显示「连接成功 · 模型已响应」→ 通过；
- 显示 401/404 → 地址或模型名不对。检查 base URL 是不是少了 `/v1`，模型 ID 是否逐字一致；
- 显示「Core 暂时无法连接」→ Core 没在跑，回第 3 步。

> 测试会产生一次极小的真实调用费用，这是正常的。
> 改完配置必须**重启 Core** 才生效，只刷新网页没用。

---

## 5. 到这里就算装完了

**必装部分结束。** 此时程序已经能用：打开管理页面能对话、能看会话记录。

**判断标准（四项全过才算完成）**：

1. Core 显示「运行中」；
2. 「管理页面」能打开，不是空白页；
3. 模型接入点「测试连接」成功；
4. 「会话记录」里能看到一条消息。

---

## 6. QQ 接入（可选，只有用户要求才做）

**只有当用户明确说"要接 QQ"时才做这一步。** 不做也完全不影响使用。

要做的话，需要装 SnowLuma（第三方 QQ 框架）：

1. 在启动器 `SnowLuma · QQ` 那一行点下载 → 安装 → 启动；
2. 打开它的 WebUI（默认 `http://127.0.0.1:5099`），用**助手号的 QQ** 登录（可能要手机确认）；
3. 在它的「网络配置」里新建一条 **WebSocket 客户端**：

   | 字段 | 值 |
   |---|---|
   | URL | `ws://127.0.0.1:5001/onebot/v11/ws` |
   | accessToken | 与 Core「系统 → 平台接入」里填的一致；默认 `test-token-123`，建议改掉 |
   | messageFormat | **Array**（不是 String） |
   | reportSelfMessage | 关 |

4. 回 Core「系统 → 平台接入」确认开关打开，令牌两边一致。

**判断标准**：「平台接入」显示「已连接」，或 Core 日志出现 `NapCat connected from 127.0.0.1`。

> 默认只对**主人私聊**发起对话。群聊或他人私聊需要到「记忆 → 社交实体」单独允许。
> 对外发送默认逐条审批，这是设计如此，不是故障。

## 常见问题：先查什么

| 现象 | 先查 | 处理 |
|---|---|---|
| 双击 EXE 没反应 | 杀毒软件 / SmartScreen | 允许运行；确认用的是 `%LOCALAPPDATA%\Abyss\app\AbyssLauncher.exe` |
| 启动器能开，网页空白 | Core 是否运行 | 点标题栏刷新；先启动 Core |
| **Core 一直「未安装」** | 是否点过下载/安装 | 回第 2 步。**程序不会自己下载** |
| Core 启动失败 | 左栏「日志」→ Core | 常见是端口 5000/5001/5002 被占 |
| 测试连接超时 | 网络 / Core 是否在跑 | 换网络、取消代理、确认 Core 运行中 |
| SnowLuma 一直重连 | URL、令牌、Array 三项 | 逐字核对，改完**重启 Core** |
| 要管理令牌 | `data\manager\service_token.txt` | 从启动器打开管理页则免登录 |

需要诊断材料时，让用户走界面拿：左栏「日志」→ 选来源 →「复制」或「打开日志目录」。

---

## 绝对不要做

1. ❌ 不要让用户装 Python、Node、Git，或手动跑 `main.py`；
2. ❌ 不要删除或移动 `%LOCALAPPDATA%\Abyss\data`（记忆、人格、账号、密钥都在里面）；
3. ❌ 不要把 Core 的 zip 解压到程序目录或数据目录；
4. ❌ 不要同时开两份启动器；
5. ❌ 不要用管理员权限运行，不要改系统环境变量"修"问题；
6. ❌ 不要把 API Key、令牌、`.env.dev` 内容发到聊天或截图；
7. ❌ 更新时若提示「检测到本地修改」，不要教用户绕过，先备份源码再处理。

## 给更深入的排查（此节可跳过）

程序实际以源码方式运行，管理服务在 `app\components\manager\source`，Core 在 `app\components\core\source`。
管理接口只监听本机 `127.0.0.1:49990`，需要 `X-Manager-Token` 头（值在 `data\manager\service_token.txt`）。

```powershell
# 确认实际位置（程序 / 数据 / 源码 / 启动脚本）
Invoke-RestMethod http://127.0.0.1:49990/v1/storage -Headers @{ 'X-Manager-Token' = '<令牌>' }

# 各组件状态
Invoke-RestMethod http://127.0.0.1:49990/v1/targets -Headers @{ 'X-Manager-Token' = '<令牌>' }

# 一键启动链路状态
Invoke-RestMethod http://127.0.0.1:49990/v1/startup -Headers @{ 'X-Manager-Token' = '<令牌>' }
```

一键启动的脚本在 `data\manager\startup_plan.py`（用户所有，更新不覆盖）；
程序自带的样板在 `app\components\manager\source\startup_plan.py`。外接 AI 改脚本前先读同目录的 `STARTUP.md`。

端口占用一览：49990 管理服务 / 5000 Core 主进程 / 5001 OneBot / 5002 Core 网页 / 5099 SnowLuma。
